# V1.1 时间轴编辑器 — 初步方案

> 状态：方案草案（2026-08-19）。依据：`docs/development-spec.md` §33（V1.1 范围）、§8（Timeline Engine 数据模型）、§36（架构决策），以及 V1 已冻结的 Runtime/Format 合同。本文档不与规格冲突；落地时如有出入，以规格为准并回写本文档。

## 1. 已有的地基（V1 真实存在、测试锁定）

V1.1 不需要动 Runtime，全部编辑能力建立在既有合同之上：

- **`AnimationDefinition` v1 数据合同**：可序列化 JSON；v1 校验器四条收口规则（无重复 track、transition 恰好一个 pose-swap、ambient/interaction 无 events、eventful alternate 拒绝、同层 easing 一致）——编辑器每次变更都实时过这个校验器，非法状态根本存不了盘。
- **同一执行路径**：`registry.register(def)` → `motionDirector.play(id)` 零分支执行，内置与用户动画无差别。
- **Registry 命名空间**：`builtin:*` 只读保护、`user:<uuid>` 用户空间、重复 id 拒绝——Preset→Customize 就是 clone + 换 id + register（§8.15）。
- **独立编辑器页 `/motion-pet-editor/`**：自包含 React 页面，宽布局、有充足空间放时间轴 UI；所有配置/资产 API 已就绪。
- **格式文档** `docs/motion-format.md`：编辑器 UI 的每个控件与格式字段一一对应。
- 独立预览页已有「贴 JSON → 校验 → 注册 → 播放」的最小闭环，是编辑器的原始形态。

## 2. 缺口（V1.1 要补的三块）

1. **自定义动画持久化**：registry 目前只在内存；用户动画需要落盘并在启动时加载。
2. **animationId 挂载**（规格 §8.14）：`TransitionConfig.preset` 是固定枚举，状态进入动画只能选内置 preset；要允许引用 `user:<uuid>`。
3. **时间轴编辑 UI** 本身。

## 3. 数据与持久化设计

```text
$DSH_HOME/motion-pet/
├── config.json          # 既有
├── assets/              # 既有
└── animations/
    └── user_<uuid>.json # 每个自定义动画一个文件（AnimationDefinition 原文）
```

- Host 新增 `animations.ts` store：启动时扫描 `animations/` 目录，逐个过 `validateAnimationDefinition`（损坏文件跳过并计入告警列表，不阻塞启动）；写盘走既有原子写。
- API（随既有 `/api/motion-pet/*` 家族）：
  - `GET /api/motion-pet/animations` → `{ customs: AnimationDefinition[], warnings: string[] }`
  - `PUT /api/motion-pet/animations/<id>` → 校验通过才保存（409/400 带字段错误）
  - `DELETE /api/motion-pet/animations/<id>` → 若被某状态引用则 `409 ANIMATION_IN_USE`（与资产删除语义一致）
- Client 启动（overlay 与编辑器页）时 GET customs → 逐一 `registry.register`。builtin 永远内置注册，custom 只是数据。
- **配置模型扩展**（§8.14 落地）：`TransitionConfig` 增加 `animationId?: string`——存在时优先于 `preset`；host validation 接受 `builtin:*` / `user:*` 两类 id 并校验存在性（不存在则 repair 回 preset 语义）。状态的 Preset 下拉变为分组列表：内置 preset + 「自定义」组。

## 4. 编辑器 UX（在 `/motion-pet-editor/` 内新增「动画」分区）

页面结构变为两区：「姿势与状态」（现有）+「动画库与时间轴」。

### 4.1 动画库面板

- 列表：内置（只读标记）+ 自定义；新建（空白 / **从 Preset 克隆**——§8.15 的 Customize 入口）、重命名、复制、删除。
- 选中即在右侧打开时间轴编辑器 + 实时预览。

### 4.2 时间轴编辑器（核心控件与格式字段一一对应）

```text
┌──────────────────────────────────────────────────────────────┐
│ name | kind(transition/ambient/interaction) | durationMs | repeat │
├──────────────────────────────────────────────────────────────┤
│ 时间标尺 0 ┈┈┈┈┈┈┈┈┈┈ 1（归一化，durationMs 决定实际时长）      │
│ ⚑ pose-swap 事件轨（transition 恰好一个，可拖动 at）           │
│ ▸ transition.scaleX   ◆——◆————◆—◆   [值/easing 编辑]          │
│ ▸ transition.scaleY   ◆——————◆——◆                            │
│ ▸ transition.y        ——◆——————◆                             │
│ [+ 添加轨道 ▾ 按层分组的白名单]                                 │
└──────────────────────────────────────────────────────────────┘
```

- **轨道**：添加/删除 track，属性来自白名单（V1.1 首批按规格：scaleX/scaleY/x/y/rotation/opacity——即现有 transition 层全量；ambient 层轨道仅当 kind=ambient）。
- **关键帧**：点击空白处新建；水平拖动改 `at`（0..1，吸附 0.01）；选中后在侧栏改 `value` 与 `easing`；双击/右键删除。value 支持数字或 ParameterizedValue（base + strength×amount 的绑定编辑）。
- **easing 编辑**：命名 easing 下拉 + cubic-bezier 四参数输入（V1.1 不做曲线图画布，规格 §2.2）。
- **事件轨**：transition kind 有且仅有一个 pose-swap 标记，拖动改 `at`；ambient/interaction 不显示事件轨（v1 合同）。
- **repeat**：once / loop / alternate / random-interval（min/max）；选 alternate 且有事件时即时校验报错。
- **实时校验**：每次变更跑 `validateAnimationDefinition`，错误内联显示在具体轨道/字段旁；非法状态禁止保存。
- **序列预览（Sequence Preview）**：右侧预览区用同一个 `<PetRenderer/>` + `motionDirector.play(id)` 循环试播当前编辑中的定义（编辑中自动重播最近一次合法状态）；可切换 strength 参数试手感。

### 4.3 挂载与使用

- 保存后动画立即可用：状态的过渡下拉出现自定义动画（`animationId` 引用）。
- **交互反馈自定义**（与本文档同期纳入）：配置增加 `interactions: { click?: animationId }`，overlay 点击宠物时播放指定 interaction 动画（现状是固定 `builtin:click-pop`）。这正是不保留双击入口的原因——点击/双击等手势语义后续统一由 interactions 配置接管。

## 5. 分期建议

```text
P0  动画持久化 + animationId 挂载 + interactions.click   → ✅ 已完成（2026-08-20，548 用例全绿）
    → 自定义动画端到端可用（编辑器页先用 JSON 文本编辑，即把 preview 的
      贴 JSON 演示搬进正式编辑器并接上保存/挂载）
P1  时间轴可视编辑 UI（轨道/关键帧/easing/事件轨/序列预览）  → ✅ 已完成（2026-08-20，588 用例全绿）
P2  Motion Pack 导入导出（motion-pack.zip，规格 §8.18）、更多 ambient channel、
    Transition Matrix override（success→idle 与 error→idle 区别退出感）
```

P0 就把「自定义动画能用」这条链路打通（性价比最高）；P1 是体积最大的 UI 工程；P2 都是数据层扩展，Runtime 不动。

**P0 落地与本文档的出入**（2026-08-20 补记）：动画按 `animations/user_*.json` 每动画一文件存储（非单 animations.json）；删除保护错误码为 `ANIMATION_IN_USE`；`interactions.click` 在 P0 之前已随用户反馈迭代落地（含闪现姿势），P0 仅把自定义 interaction 纳入下拉。

## 6. 明确不做（规格 §2.2 护栏）

任意 CSS property、JS 表达式、脚本轨、通用曲线图编辑器、骨骼/Live2D、视频编辑——目标始终是 **Pet-specific Animation Editor**。

## 7. 测试策略

- P0：animations store（加载/损坏跳过/原子写/409 引用保护）、animationId 验证与挂载、registry 启动加载、interactions.click 行为（含未设置时回落 click-pop）。
- P1：编辑器状态机（轨道/关键帧增删改、拖拽 at 的吸附与 clamp、easing 编辑、实时校验阻断保存）、序列预览与编辑联动。
- 全程沿用既有 fake-animate + jsdom 设施；E2E 用 CDP 截图抽查。
