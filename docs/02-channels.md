# 02 · 资源与仲裁

> 状态：已定（2026-10-19）

v0 最大的问题是「当前显示哪张图」由好几处各自写入（状态切换、flashPose 账本、点击恢复、roamer 的 1ms hack）。本文规定：**宠物的每样可见属性都是一个通道，每个通道有且只有一套仲裁规则，所有写入者（包括内置功能）都通过同一套 API。**

## 1. 通道一览

### 每只宠物

| 通道 | 内容 | 仲裁规则 |
|---|---|---|
| `state` | 当前状态键 | 独占栈：最高优先级的意图生效 |
| `clip` | 显示哪个片段（直接指定，绕过状态键） | 独占栈；**有 clip 意图时覆盖 state 解析出的片段** |
| `motion` | 变换 | **叠加栈**：所有活跃意图按层合成（见 03） |
| `position` | 宠物在桌面上的位置 | 独占租约（默认 preempt）；**生效中的租约释放时，它最后的值成为新的基准位置**（拖完松手宠物留在原地），基准位置会持久化 |
| `bubble` | 气泡文字 | 队列（按优先级插队，同优先级先来先到） |
| `input` | 点击 / 拖拽 / 悬停 | 广播。事件：`hover-start/end`、`down`、`up`、`click`、`context`、`drag-start/move/end`；按下后移动超过 4px 才算拖拽 |

### 全局

| 资源 | 规则 |
|---|---|
| 舞台层 | 插件可插入 DOM / Canvas 层，声明 z 序和命中区域；不仲裁，各画各的。z < 0 在宠物下面，z ≥ 0 在上面；层默认 `pointer-events: none`，需要接收鼠标的子元素自己设 `auto`，并通过 `hitTest` 告诉内核那里要可点 |
| 设置页、托盘菜单项 | 声明式贡献，按插件分组展示 |

## 2. 独占栈的规则

```ts
const lease = pet.channel('state').request({
  owner: 'roamer',          // 自动取插件 id，调试和冲突提示用
  priority: 20,
  value: 'roamer.doze',
  releaseOn: 'never',       // 或 'signal-change'：大脑输出一变就自动释放
})
lease?.update('roamer.walk')
lease?.release()
lease?.onRevoked(() => { /* 被更高优先级抢走 */ })
```

- 栈底永远是大脑输出（优先级 0），不可释放。
- 新请求优先级 **高于** 当前栈顶 → 立即生效；原栈顶 **不被撤销**，只是被压住，上面的释放后自动恢复。
- 新请求优先级 **等于或低于** 栈顶 → 依然入栈（排在同优先级的后面），等上面的释放后生效。`request` 返回值上有 `active: boolean` 和 `onActiveChange`。
- 只有「抢占式」请求（`preempt: true`）会撤销同优先级以下的持有者——用于位置这类不能"被压住还以为自己在控制"的资源。`position` 默认 preempt。

> 为什么默认是「压住」而不是「撤销」：v0 的 roamer 需要在被打断后自己恢复，正是因为没有栈。有了栈，恢复是免费的。

### 约定的优先级段

| 段 | 用途 |
|---|---|
| 0 | 大脑（栈底） |
| 10–39 | 插件的常驻行为（漫游、HUD 联动） |
| 40–69 | 插件的短时动作（一次性表情、通知） |
| 70–89 | 内置交互（点击反馈） |
| 90–99 | 用户直接操作（拖拽） |

用户可以在设置里按插件调整偏移量（v1 只做「全局开关某插件对某通道的写权」，不做数字微调）。

## 3. 叠加栈（motion）

motion 通道不选赢家，而是把所有活跃意图合成。每个意图是一个动作源（见 03 `MotionSource`），带 `layer`、`blend`（add / override）和 `weight`。插件之间不冲突，最多是效果叠加得过头——这是作者自己的事。

需要「独占运动」的插件（比如想完全接管姿态的物理插件）用 `blend: 'override'` 放在较高的层即可。

## 4. 片段与状态的关系

两种控制粒度，供插件按需选：

- **控制 `state`（推荐）**：`showState('roamer.doze')`。具体显示什么由宠物包决定；宠物包没配这个键就按回退链落到 `idle`。同一插件换宠物包会有不同表现。
- **控制 `clip`（逃生口）**：直接指定一个片段（宠物包里的，或插件自带的资源）。用于插件确实需要特定画面的场景。

解析顺序：`clip` 栈顶有意图 → 用它；否则 → `state` 栈顶的状态键 → 外观解析。

## 5. 调试面板（必须有）

设置里提供一个「通道检查器」：每只宠物每个通道当前的栈内容（owner、优先级、值、是否活跃）。多插件打架时，用户和作者都能一眼看出是谁。
