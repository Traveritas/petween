# 00 · 愿景与边界

> 状态：已定（2026-10-19）

## 一句话

一只（或几只）住在桌面上的宠物，陪你看 AI agent 干活；谁都能用 AI 生成的图给它换形象，谁都能写插件教它新本事。

## 三类用户

| 用户 | 想做什么 | 我们交付 |
|---|---|---|
| **普通用户** | 装上就能用，接上自己用的 agent，换个喜欢的形象 | 安装包、一键接入 agent、宠物包导入 |
| **画图的人** | 用 AI 生成每个状态的图/GIF/视频，做成宠物包分享 | 宠物包格式（纯数据）+ 可视化编辑器 + 导入管线 |
| **写插件的人** | 用代码让宠物做任何事 | 插件 API（L0–L4 分级，最高可替换核心部件） |

## 设计原则

1. **内核极小，内置功能也是插件。** 内置功能不允许走第三方插件走不了的后门。检验标准：任何内置功能都能被一个第三方插件完整替换。
2. **数据能表达的用数据，代码只在需要时介入。** 宠物包是纯数据（可分享、可视化编辑、不执行代码）；插件可以注册新的"数据类型"（新动作类型、新片段类型），让数据层的表达力随插件增长。
3. **共享资源必须仲裁。** 宠物显示什么、怎么动、在哪里、说什么——每样都有明确的所有权规则（见 02），不允许"谁最后写谁赢"。
4. **画面和运动分离。** 片段只管画面，动作只管变换，状态只管语义（见 03）。
5. **装插件 = 信任作者。** 不做沙盒；权限声明只用于向用户展示，不做拦截（VS Code / Obsidian 模式）。
6. **多宠物是一等公民。** 所有 API 都以宠物实例为单位，即使用户只养一只。

## v1 范围

- 平台：**Windows 优先**；macOS 次之（需开启私有 API 以支持透明窗口，不上 App Store）；Linux 尽力而为。
- Agent：Claude Code、Codex 两个内置接入插件；接入层对第三方开放。
- 美术：静态图、GIF、短视频（导入时统一转为帧序列）。
- 动作：K 帧、弹簧、噪声、正弦四种内置动作类型；插件可注册新类型。
- 多宠物：数据模型和 API 全面支持；UI 提供「一只管全部」「每个会话一只」两种绑定规则。
- 内置插件：Claude Code 接入、Codex 接入、默认大脑、气泡、漫游（roamer）、物理（拖拽/抛掷）、统计 HUD。

## 明确不做（v1）

- Live2D / Spine / 3D 渲染器。接口（L4 渲染器槽）留着，不实现。
- 插件沙盒、插件市场、在线账号。
- 内置 Node 运行时。需要 Node 的插件自带可执行文件（L4 sidecar）。
- 导入时自动抠图（以后可做成插件）。
- 宠物包内含代码。宠物包永远是纯数据。

## 不是目标

- 不追求和 v0（petween-desktop）的配置/宠物包兼容。提供一次性导入工具即可。
- 不追求和 DSH 插件形态兼容（已停止维护）。
