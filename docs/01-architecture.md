# 01 · 架构总览

> 状态：已定（2026-10-19）。技术栈已由 [08 原型](08-spike.md) 第一轮验证：保持 Tauri 2（多显示器待补测）。

## 1. 技术栈

**Tauri 2。Rust 层薄，TypeScript 层厚。**

| 层 | 语言 | 职责 | 不做 |
|---|---|---|---|
| 宿主（host） | Rust | 窗口、托盘、开机自启、全局快捷键、单实例；hook HTTP 服务（axum，仅监听 127.0.0.1）；文件存储；插件发现与加载；能力接口（fs / shell / http / 文件监听 / 启动子进程） | 任何宠物逻辑 |
| 运行时（runtime） | TS，跑在舞台 webview | 内核（插件、事件总线、仲裁、合成、渲染循环）+ 所有插件的前端部分 | 直接碰操作系统 |
| 设置 / 编辑器 | TS + React，独立 webview | 设置页、宠物包编辑器、插件贡献的设置页 | 持有宠物状态（只通过 API 读写） |

选择理由：安装包从约 110MB 降到约 10–20MB；宠物逻辑全在 TS 里，旧代码可移植，插件作者只需会 JS。

已知代价：Tauri 没有 forward 式鼠标穿透，需要光标轮询 + 命中检测（v0 已有此兜底）；macOS 透明窗口需开私有 API。

## 2. 窗口模型

```
宿主进程（Rust）
├─ 舞台窗口 × 每块显示器一个   透明、无边框、置顶、铺满该显示器工作区
│    └─ 运行时：内核 + 插件前端 + 所有宠物的渲染
├─ 设置窗口（按需创建）
└─ 插件窗口（插件可申请，L3）
```

- **每块显示器一个透明舞台**：所有宠物和插件绘制物（便签、粒子、HUD）都在舞台里。选它而不是「每只宠物一个小窗口」，是为了让插件可以在屏幕任何位置作画。
- **鼠标穿透**：宿主以约 60Hz 轮询光标位置，发给对应舞台；运行时做命中检测（宠物按片段的透明通道，插件层按自己声明的命中区域），回报「是否命中」；宿主据此切换 `set_ignore_cursor_events`。
- **坐标**：对外统一使用全局桌面坐标 = **物理像素 ÷ 主显示器缩放**（单屏时就是逻辑像素；混合 DPI 时各屏仍一致）。宠物尺寸、动作位移也用这个单位，各舞台按自己的缩放换算。宠物跨显示器时，由内核在两个舞台间交接渲染，插件无感。
- **不抢焦点**：舞台窗口带 `WS_EX_NOACTIVATE`，点宠物不会把键盘焦点从用户正在用的程序抢走。
- **帧率**：只有环境动作（base 层循环、帧序列片段）在动时按 30fps 渲染；有拖拽、过渡、物理、交互层动作或插件逐帧回调时 60fps；什么都不动时停止渲染循环。
- **只有一个内核**：多个舞台窗口里，只有一个（主显示器的）运行内核与插件，其他舞台是「哑渲染端」，接收渲染指令和回报输入。这样插件不会被加载多次。
- **设置窗口**：按需创建（托盘「设置…」或 `petween --settings`；已在运行时由单实例转交）。它不持有任何宠物状态，所有读写都经 `src/shared/admin.ts` 定义的 RPC 交给内核（Tauri 事件 `admin-call` / `admin-result`，带启动握手）。
- **已知限制（M0）**：插件舞台层（`stage.addLayer`）目前只出现在主显示器的舞台上；跨屏的插件绘制等多屏实测后再设计。

## 3. 内核：只做五件事

| # | 职责 | 说明 |
|---|---|---|
| 1 | 插件生命周期 | 发现、按依赖排序加载、激活、停用；插件注册的一切在停用时自动清理（参考 cordis 的上下文作用域） |
| 2 | 事件总线 | agent 信号、用户输入、插件间消息；带类型的主题 |
| 3 | 资源仲裁 | 每只宠物的片段 / 动作 / 位置 / 气泡 / 输入通道，以及全局的舞台层（见 02） |
| 4 | 存储 | 宠物包、宠物实例、插件设置（每个插件独立命名空间） |
| 5 | 合成与渲染循环 | 每帧：求值动作栈 → 合成变换 → 推进片段播放器 → 绘制 |

其余一切——agent 接入、状态逻辑、漫游、物理、气泡外观、HUD——都是插件。

### 注册表（扩展点）

内核维护几张注册表，内置实现和插件实现都通过它们登记，地位相同：

| 注册表 | 登记什么 | 内置实现 |
|---|---|---|
| `connectors` | agent 接入（把 hook 变成信号） | claude-code、codex |
| `brains` | 大脑（信号 → 状态键） | default（稳定化规则） |
| `motionTypes` | 动作类型 | keyframes、spring、noise、sine |
| `clipTypes` | 片段类型（播放器） | still、frames、video |
| `transitionTypes` | 片段之间的过渡方式 | cut、crossfade、onMarker、afterLoop |
| `bindingRules` | 会话 → 宠物 的绑定规则 | single、perSession |
| `renderers` | 渲染器（v1 只有一个） | dom2d |

## 4. 每只宠物的管线

```
 Agent 事件（connector 插件归一化，带 sessionId）            用户输入（点击/拖拽/悬停）
        │                                                          │
        ▼  绑定规则：哪些会话驱动这只宠物                             │
 ┌─────────────┐                                                   │
 │ 大脑         │  每只宠物一个独占槽；默认 = 稳定化规则               │
 │ 信号 → 状态键 │  例：active.command.Bash / waiting / success     │
 └─────┬───────┘                                                   │
       │ 状态键（优先级 0 的意图）                                    │
       ▼                                                           ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 仲裁器（按通道，见 02）  ← 插件意图（带优先级的租约）                    │
 └─────┬────────────────────────────────────────────────────────────────┘
       │ 每个通道当前的赢家
       ▼
 ┌─────────────────────┐
 │ 外观解析              │  查宠物包：状态键 → 片段 + 动作，逐级回退（见 04）
 └─────┬───────────────┘
       ▼
 ┌─────────────────────┐
 │ 合成器               │  片段通道（一个画面）+ 动作栈（多层叠加，见 03）
 └─────┬───────────────┘
       ▼
     渲染器 → 舞台
```

要点：

- **状态键是大脑和外观之间唯一的语言。** 大脑不知道有哪些图；宠物包不知道状态是怎么算出来的。
- **大脑的输出只是优先级 0 的意图。** 插件的意图可以盖过它，释放后自动回到大脑的结果（不需要任何「恢复」操作）。
- **显示什么 = 纯函数**：`resolve(各通道意图栈, 宠物包)`。任一意图变化就重算，不存在「谁记得恢复」的问题。

## 5. 数据与目录

```
<app data>/
├─ pets/            宠物包（每个一个文件夹；导入导出为 .petpack = zip）
├─ plugins/         第三方插件（每个一个文件夹，含 manifest）
├─ instances.json   宠物实例：用哪个宠物包、绑定规则、位置、缩放
├─ settings/        每个插件一个 JSON（命名空间隔离）
└─ cache/           导入管线产物（帧序列、命中掩码）
```

内置插件随安装包分发，不放在 `plugins/` 里，但走同一套加载流程。

## 6. 宿主 ↔ 运行时通信

- 运行时 → 宿主：Tauri `invoke`（能力调用：读文件、执行命令、发请求……），按插件 id 记账。
- 宿主 → 运行时：Tauri 事件（hook 到达、光标位置、显示器变化、托盘点击）。
- hook 服务：宿主收到 `POST /hook/<connectorId>` 后，**原样**（body + query + headers 子集）转发给运行时，由对应 connector 插件解析。宿主不理解任何 agent 的格式。
